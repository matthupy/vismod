Tuning extraction density

Fewer frames per video = lower vendor cost, but the two quality risks pull opposite ways:

Recall — "single-frame flags" counts flagged videos where exactly ONE frame carried the detection. A sparser workflow would likely have missed those. If this number is a meaningful share of flagged videos, you are at the recall floor: don't thin extraction further.

Precision — a high "avg flagged frames / flagged video" means detections have margin (many frames agree), so thinning extraction saves cost without losing them; it also reduces the chances for a single borderline frame to flag a clean video.

Operational controls

Pause stops accepting new jobs (intake returns 503 with a retryable signal); in-flight jobs finish normally. This is the whole control surface by design.
